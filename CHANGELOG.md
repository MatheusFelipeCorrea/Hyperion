### Changed
- **`.github/dependabot.yml` is no longer managed by `hyperion:upgrade`** — it is this repo's own config (updates now target `dev`), so upgrading the kit no longer overwrites a product's Dependabot setup; `distribution-purity-check` fails if it is listed in `MANAGED_FILES` again, like CODEOWNERS/FUNDING.yml. ### Fixed
- **Jira sync on Jira Cloud** — Cloud removed `/rest/api/2/search`, so every lookup failed. Searches now use `/rest/api/2/search/jql` (paged by `nextPageToken`) and fall back to `/rest/api/2/search` on Jira Data Center. Forward sync also read only the first 50 matches, creating duplicate issues on bigger projects; it now indexes every match with one paged search. Forward applies `statusMap` before picking the transition, reverse sets `board_sync_at` from `updated`, and a create without a key no longer calls `/issue/undefined/transitions`. The Data Center fallback also kicks in on a 405, and when both endpoints fail the error names both. When the workflow has no transition to the mapped status, forward tries the card's own status, and it no longer transitions an issue that is already in the target status (`STATUS_UNCHANGED`). When several issues carry the same `CARD_ID`, forward updates the open one with the lowest number (`pickCanonicalIssueForCardId`, like the other backends) instead of the most recently updated one.
- **Azure Boards sync could not create work items** — the create call was missing the `$` before the work item type (`/_apis/wit/workitems/$Task`), and both WIQL queries ordered by `System.Changed Date` instead of `System.ChangedDate`, which Azure rejects. Reverse sync also stopped at the first 100 work items; it now reads every match, 200 per batch call (the `workitemsbatch` limit). Both WIQL queries are now scoped to the configured project (`[System.TeamProject] = @project`), so a card in another project of the same organization is no longer matched. Forward sync runs one WIQL query plus batch reads for the whole run instead of a WIQL query and a GET per candidate for every card. Batch reads use `errorPolicy: omit`, so a work item deleted between the query and the read is skipped instead of failing the sync.
- **`hyperion:create` copied the Hyperion repo's own tooling into new products** — the nested kit got `scripts/kit/`, the `kit:*` npm scripts and every non-`hyperion-*` workflow (QA release gate, branch flow…). They are now left out of the scaffold. The nested kit's `package.json` is also renamed to `<product>-hyperion` and loses the kit's `repository`/`bugs`/`homepage`, so `distribution-purity-check` no longer mistakes a product for the Hyperion repo.
- **GitLab sync duplicated issues and could lose a card's status** — forward looked each card up in the first 20 search results, so on bigger projects it created duplicates; it now indexes every `CARD_ID` issue with one paged search (100 per page, following GitLab's `x-next-page` header, with a 200-page safety cap that fails loudly instead of syncing a partial list; reverse also lost its 10-page cap). The `status:` label now goes with the create/update itself instead of a second call, so a failed state change no longer leaves the issue without it (reverse sync used to read that as "In Progress"). `status:*` entries in a card's categories give way to that label. An update no longer wipes labels added on GitLab: only `status:*` labels and the card's current and previously synced categories are replaced, and everything else on the issue is kept. When several issues carry the same `CARD_ID`, forward updates and reverse reads the open one with the lowest iid (`pickCanonicalIssueForCardId`, like the other backends). Reverse logs `#iid` instead of `!iid`.
- **GitHub card sync misplaced Parent links, misread `project.yml` and mislabeled dry-run plans** — a card whose `## Parent` section wasn't the first line got a second Parent section appended; a new Parent link landed at the end of the issue instead of above `## Summary`/`## Resumo`/`## Resumen`; the `management:` block of `project.yml` was ignored when it was the last block and cut short at any "Z" in a value (so `backend`, `org`, `status_map`… silently fell back to defaults); and `--dry-run` showed CREATE for cards whose issue already exists. Dry-run now shows UPDATE for those and still writes nothing.
- **`coverage-gate --diff-base` hung and exited with code 13** — `coverage-gate.mjs` and `diff-coverage.mjs` imported each other under a top-level `await`. The shared ignore-glob helpers moved to `coverage-ignore.mjs`, so diff coverage runs again.
- **`--refresh-gates` never re-rendered a generated `hyperion-product-ci.yml`** — its header mentioned `hyperion:no-auto-refresh`, so every generated file looked pinned. The opt-out now only counts when a comment line starts with the marker; files the user pinned are still skipped.
- **`pipeline-apply` failed with `ENOENT` in nested layouts** — static workflow templates were read from the product root instead of `kit.root`.
- **`hyperion-cards-pr-recheck.yml` ignored `kit.root` and the default branch** — `pipeline-apply` rendered it without options, and the template hard-coded `base: "main"` with no `working-directory`. It now runs inside `kit.root`, lists PRs against the detected default branch, and `--refresh-sync` / `doctor` flag older copies.
- **Generated workflows could target the checked-out branch** — without `origin/HEAD`, the default-branch fallback was the current branch, so running `pipeline-apply` on `feature/x` wrote `feature/x` into workflow triggers and the recheck `base:`. Workflow generation now trusts only `origin/HEAD` and otherwise assumes an existing `main`/`master` (or `main`), warns about it, and skips the recheck base-branch check.
- **`appendForkGuardJob` produced invalid YAML** — the `board-guard-fork` job lost its indentation under `jobs:`.
- **Duplicate e2e job ids in product CI** — an app with both Playwright and Cypress got two `e2e-<app>` jobs; they are now `e2e-<app>-playwright` and `e2e-<app>-cypress` (single-tool apps keep `e2e-<app>`).
- **E2E configs attached to the wrong app** — a Playwright/Cypress config outside any app was given to the first Node app. It now belongs to the app whose directory contains it (the root app only if one exists), runs with `--config`/`--config-file` when it isn't at the app root, and gets no job when no Node app contains it. E2E job ids and their owning app are now part of the gates hash, so an existing product CI with duplicate or misattached e2e jobs is reported outdated.
- **Rails apps lost `db:prepare` and the migrations gate** — gate detection skipped every `bin/` directory, so `bin/rails` was never seen. `bin/` next to a `Gemfile` is scanned now; other `bin/` folders are still treated as build output.
- **Wrong toolchain `versionSource` for PHP and Ruby** — a version read from `.tool-versions` was reported as `composer.json` / `.ruby-version`.
- **Upgrade note: one-time "outdated" product CI warning** — the three fixes above (e2e ownership, Rails `bin/`, PHP/Ruby `.tool-versions`) change the gates hash. Products with e2e configs, a Rails app, or a PHP/Ruby version from `.tool-versions` will see `hyperion-product-ci.yml differs from ci.gates` once after upgrading; run `npm run hyperion:pipeline-apply -- --refresh-gates --yes` to re-render it.
- **MCP example config didn't authenticate in Cursor** — `.github/mcp/servers.example.json` used `${JIRA_URL}`-style placeholders, which Cursor doesn't expand (it needs `${env:NAME}`), so the Jira, Linear and GitLab servers received the literal text. The example now points at each vendor's official server — Atlassian Rovo, Linear (read-only endpoint by default), GitLab's built-in MCP — signed in with OAuth instead of `npx -y` community packages holding your token; Azure DevOps keeps Microsoft's `@azure-devops/mcp`, which runs locally through `npx` (pin a reviewed version). The Hyperion server path is absolute (`${workspaceFolder}/…` in Cursor; Claude Desktop needs the full path). The README and the `integration-bridge` skill say to read the board through MCP and change cards in the repo, since cards-sync is the source of truth, and that sync still needs the backend's token in `.env` (`JIRA_API_TOKEN`, `LINEAR_API_TOKEN`, `GITLAB_TOKEN`, `AZDO_PAT`). They also state each server's limits: Atlassian Rovo is Jira Cloud only and consumes Rovo credits (Data Center relies on cards sync), GitLab needs 18.6+ with MCP access enabled by a group owner or instance admin, and Atlassian and GitLab have no read-only endpoint, so sign in with a least-privilege account.
- **`hyperion:cursor` (`install-cursor-rules.mjs`) never installed anything** — its source and target were both `<cwd>/.cursor/rules/hyperion.mdc`. The source is now the kit's own rules (found from the script's location) and the target the repo it runs in; re-runs are no-ops, outdated rules are updated, and a kit nested under the cwd (`your-product/Hyperion/`) leaves the product's pointer shim from `hyperion:init -- --adopt` alone. `hyperion:setup` / `hyperion:init` now really install the rules.
- **`install-product-shims.mjs --force` logged "Added kit.root" without writing it** when the existing `.github/project.yml` had no `version:` line. `--force` now prepends the `kit:` block; without `--force` it says why nothing was added.
- **`hyperion:setup -- --languages ,` passed validation and died with a FATAL** later. Empty or blank `--languages` entries (`,`, `pt-BR,,en`, `--languages=`) are rejected up front with a message in the repo language (new `setup.languagesEmpty` catalog key in `en`, `pt-BR`, `es`).
- **`hyperion:doctor` swallowed a failing cards-sync doctor on Windows** — when the cards doctor printed "Doctor finished." but exited non-zero (e.g. Status column missing Hyperion options), a Windows-only "cleanup quirk" branch turned the failure into a warning and exit 0. The cards doctor's exit code now fails the kit doctor on every platform.
- Removed dead code: an unreachable `preserve` branch in `buildUpgradePlan` (no managed path is ever client-owned; a test now enforces it) and a no-op `dryRun ? argv : argv` in `scripts/hyperion/sync.mjs`.
- **`cards:doctor` flagged localized boards** — the Status column check only accepted the English names, so a `pt-BR` board with "Em Progresso"/"Concluído" was reported as missing every column. It now also accepts the names from `optionMapByLocale` for the repo locale.
- **`ci.hyperion.product_ci: true` never took effect** — the value was parsed as the string `"true"` and compared to a boolean, and the schema rejected YAML booleans. Both forms are accepted now, and `true` generates `hyperion-product-ci.yml` alongside existing product CI as documented. `pipeline-detect` also reads `project.yml` from a nested kit (`kit.root`).
- **Reconcile never resurrects deleted cards** — a card known to the snapshot, tombstoned, or deleted in git history is reported instead of recreated from its issue; closed issues without a card are reported, not imported. Recency uses the card's last commit time (or mtime when dirty), not the checkout time. Cards whose forward push failed keep their previous snapshot so they retry.
- **`patchCardFrontmatter` ignored title updates** from the board.
- **`migrate-layout.mjs` moved real card files on disk live by default**, with no `--yes` required — the one remaining cards-sync script that didn't follow the dry-run-by-default convention. Now previews by default; `--yes` required to actually move files.
- **README never mentioned the `dev → qa → main` (+ `internal`) branch model** — only `CONTRIBUTING.md` explained it, so a first-time contributor following just the README would try to commit straight to `main`. **Quickstart sent Node-less users straight into `npm install`**, failing on `Cannot find package 'ajv'` before they discovered the Docker path — both fixed with an earlier fork point in the Quickstart section and a "Fluxo de branches" link.
- **`sync.mjs` could create a duplicate GitHub Project** when automatic Project discovery was ambiguous (an account with more than one Project candidate) — `pickBestGitHubProject` picked the first regex match instead of checking for uniqueness, and the caller didn't check for an "ambiguous" discovery result before falling through to auto-create. Fixed both: `pickBestGitHubProject` now prefers a repo-named board and only returns a single unambiguous match, and auto-create is skipped when discovery reports ambiguity.
- **`install-hook.mjs` had no entrypoint guard** — importing the module (as its own test did) ran `main()` for real, silently installing/mutating a pre-commit hook in whatever repo happened to be the current working directory. Guarded with the same `pathToFileURL` pattern used elsewhere in the kit; added regression tests (import vs. direct-run).
- **`install-hook.mjs` assumed `.git` is always a directory** — broke with `ENOENT` in a git worktree or submodule, where `.git` is a file pointing elsewhere. Now resolves the real hooks directory via `git rev-parse --git-path hooks`; added a regression test that reproduces a real worktree.
- **`sync.mjs`/`doctor.mjs` fell back to your local `gh auth token` session silently** when no `PROJECT_SYNC_TOKEN`/`GITHUB_TOKEN` was set — making real GitHub API calls under your own identity with no warning. Both now log an explicit warning when this happens; `doctor.mjs` no longer shows a green check for "no token available".
- **`pipeline-lib.mjs`'s default-branch fallback read `.git/refs/heads/*` directly** — same worktree/submodule blind spot as above. Now asks git itself (`git rev-parse --verify`).
- **`getLabelId`'s create/retry race (PR #66) had zero unit coverage** — only ever exercised by the opt-in E2E test. Exported it and added mocked-fetch tests covering the create path, the "name already taken" race, and unrelated errors re-throwing.
- **Backend config errors (Jira/Azure/GitLab/Linear) printed a raw stack trace** for an entirely expected "you haven't configured this backend yet" case. `sync.mjs` now prints just the actionable message unless `--verbose` is passed.
- **`.github/mcp/servers.example.json` referenced two npm packages that don't exist** (`@atlassian/mcp-server-jira`, `@azure-devops/mcp-server`) — replaced with real packages (`mcp-atlassian`, the official `@azure-devops/mcp`), and aligned the README's server names with the JSON's actual keys.
- **`hyperion:llm-eval`'s live mode was 100% inoperative** regardless of API key — `.github/skills/eval/prompts/` didn't exist, and `ANTHROPIC_API_KEY` was accepted by the key check but the Anthropic call path threw "not wired yet". Implemented the real Anthropic call, added the missing prompts, and documented both eval modes in a new `.github/skills/eval/README.md`.
- **English PM onboarding was a redirect loop** — `trilha-pm.md`'s English section pointed at `learning-path-en.md`, which pointed back at `trilha-pm.md` (Portuguese-only), with no real English content anywhere. Added `pm-track-en.md` and pointed both sides at it directly.
- **`.gitignore`'s kit-managed lines were never propagated by `hyperion:upgrade`** — adopters missed new ignore rules (e.g. `sync-history.jsonl`) added to the kit's own `.gitignore`. Added a marker-guarded merge (`mergeGitignore`), same pattern as the existing `package.json` merge, so adopter-added lines are never touched.
- **`.github/FUNDING.yml` shipped live** (not as a template) with the maintainer's personal GitHub handle, and was in `MANAGED_FILES` — every `hyperion:upgrade` silently propagated it to adopters. Removed from `MANAGED_FILES` (same treatment as `CODEOWNERS`: this repo's own config, not adopter-facing), documented in `GETTING-STARTED.md`'s copy table.
- An internal maintainer planning doc (`gap-closure-action-plan.md`, referencing an internal dogfood repo and token setup notes) was committed directly under `.github/plans/` and shipped in every clone/`npm pack` — moved into the already-`.gitignore`d `.github/plans/implementations/`.
